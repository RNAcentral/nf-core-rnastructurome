## Introduction

This document describes the files produced by the pipeline and where to find them.
All paths below are relative to `--outdir`.

## Output layout at a glance

```text
<outdir>/
├── fastqc/
├── cutadapt/
├── bowtie_build/ bowtie_align/ bowtie2_build/ bowtie2_align/
├── samtools_*/
├── umi_tools_*/                       (if UMI options are enabled)
├── count/
├── norm/
├── fold/
├── multiqc/
└── pipeline_info/
```

The exact presence of some directories depends on your chosen alignment / UMI settings.

## Pipeline overview

Major stages:

1. Read QC (`FastQC`, pre and post trimming)
2. Read processing and alignment (`cutadapt`, `bowtie`/`bowtie2`, `samtools`, optional `umi_tools`)
3. RNAframework reactivity processing (`rf-count`, `rf-norm`, `rf-fold`)
4. Aggregated reporting (`MultiQC` + `pipeline_info`)

## FastQC

### Files

- `fastqc/*_fastqc.html`
- `fastqc/*_fastqc.zip`

### Meaning

FastQC is run before and after trimming and reports per-base quality, sequence content, adapters, and overrepresented sequences.

## RNAframework

### `count/` (`rf-count`)

Per-sample count directories, e.g. `count/<sample>_rfcount/`.

Typical files:

- `*.rc`: raw per-position counts (RT-stop or MaP, depending on sample principle)
- `*.rc.rci`: optional index sidecar
- `*.rfcount_summary.tsv`: parsed per-sample summary metrics extracted from `rfcount.log`
- `plots/*.pdf`: count plots (always generated by this pipeline)

### `norm/` (`rf-norm`)

Per-group normalization directories, e.g. `norm/<group>_norm/`.

Typical files:

- `*.xml`: normalized reactivity profiles for downstream folding
- `rfnorm.log`: raw `rf-norm` console output
- `plots/*.pdf`: normalization plots (always generated by this pipeline)

### `fold/` (`rf-fold`)

Per-group fold directories, e.g. `fold/<group>_fold/`.

Typical files:

- `structures/`: inferred secondary structure outputs (dot-bracket by default)
- `rffold.log`: raw `rf-fold` console output
- `plots/`: fold report plots
- `dotplot/`: dotplot outputs when dotplot mode is enabled
- `error.out`: fold-level errors/warnings, if any

Notes:

- Dot-bracket output is the default structure format.
- CT output is additionally produced when `--rffold_ct` is enabled.
- Graphical fold reporting is enabled by default.
- If `rf-fold` reports errors or produces no structures, the task now fails (pipeline stops instead of silently continuing).

## MultiQC

### Files

- `multiqc/multiqc_report.html`
- `multiqc/multiqc_data/`
- `multiqc/multiqc_plots/`

### Meaning

`multiqc_report.html` is the main summary report for pipeline QC and alignment metrics.

It also includes a custom `Count Progression` table with:

- mapped reads before deduplication
- mapped reads after deduplication
- reads removed by deduplication
- `rf-count` covered transcripts

## Pipeline information

### Files

- `pipeline_info/execution_report.html`
- `pipeline_info/execution_timeline.html`
- `pipeline_info/execution_trace.txt`
- `pipeline_info/pipeline_dag.dot`
- `pipeline_info/pipeline_dag.svg`
- `pipeline_info/params.json`
- `pipeline_info/samplesheet.valid.csv`
- `pipeline_info/nf_core_rnastructurome_software_mqc_versions.yml`
- `pipeline_info/pipeline_report.html` / `pipeline_report.txt` (when email reporting is enabled)

### Meaning

These files are for run provenance, traceability, and troubleshooting resource/runtime issues.

## Troubleshooting missing outputs

1. Check process status in `.nextflow.log` and `execution_trace.txt`.
2. For fold problems, inspect `fold/<group>_fold/error.out`.
3. Re-run with `-resume` after fixes to avoid recomputing successful tasks.
